Chapter 6 – Creating a server API in PHP

Script: Chapter 6
Folder: /WEBAP/Exercises/ch06/ – one folder ex_xx per exercise. Comments marked TODO show where to write your code. Folders containing only a README.txt start from a copy of the previous exercise.

In these exercises you write the server side of a SPA: a small API that answers every request with JSON in the same format: {"success": true, "data": …} or {"success": false, "error": "…"} with a suitable HTTP status code. Test your API with the API tester (Exercises/tools/api-tester.html) – a client page is only needed in chapter 7.

Exercises 2 – 4 use the database webap2_db (tables tblTodo and tblFavorite); the connection is returned by getPdo() of common/config.php.

Exercise 6.1 – A notes API with a JSON file

Folder: ch06/ex_01/   open folder   Files provided: api/, data/

Structure: ex_01/api/helpers.php, ex_01/api/notes.php, ex_01/data/notes.json (section 6.2).

  1. Write the helper functions sendJson(), sendError() and requireMethod() in helpers.php (section 6.3).
  2. notes.php reads the parameter action and reacts with a switch (section 6.4):
    • GET ?action=list → all notes
    • POST ?action=add with title, text → creates a note with id (uniqid()) and date, answers with status 201 and the new note. Without title: status 400.
    • POST ?action=delete with id → deletes the note, 404 if it does not exist.
    • any other action → status 400 with a helpful message.
  3. The notes are stored in data/notes.json (section 6.7).
  4. Test every action with the API tester, also the error cases (GET for add, missing title, wrong id). Check the status codes.

Exercise 6.2 – A todo API with the database

Folder: ch06/ex_02/   open folder   Files provided: api/

Write a complete CRUD API for the table tblTodo (idTodo, dtTitle, dtDone, dtCreated). Copy helpers.php from exercise 1.

RequestParametersAnswer
GET ?action=list–all todos, open ones first
GET ?action=getidone todo (404 if unknown)
POST ?action=addtitlethe new todo, status 201
POST ?action=updateid, titlethe changed todo
POST ?action=toggleidthe todo with inverted done
POST ?action=deleteid{"deleted": id}
  1. Use prepared statements for all values from the client.
  2. Do not send the column names to the client: convert each row into {"id":1,"title":"…","done":false,"created":"…"} with a function format($row) (section 6.6).
  3. Write a function findTodo($pdo, $id) that returns the row or stops with 404 – use it in get, update, toggle and delete.
  4. Catch PDOException and answer with status 500.

Exercise 6.3 – Receiving JSON in the request body

Folder: ch06/ex_03/   open folder   Files provided: README.txt

Many clients send their data as JSON instead of form data (section 6.5). Copy exercise 2 into ex_03.

  1. Add a function getInput() to helpers.php: if the header Content-Type contains application/json, it reads the body with file_get_contents("php://input") and decodes it; otherwise it returns $_POST. Invalid JSON → status 400.
  2. Use getInput() instead of $_POST in all actions.
  3. Test with the API tester: the same action once with form data and once with a JSON body {"title": "Learn JSON"}. Also test invalid JSON.

Exercise 6.4 – Combining internal and external data

Folder: ch06/ex_04/   open folder   Files provided: api/

An API for favourite cities (table tblFavorite: idFavorite, dtName, dtCountry, dtLatitude, dtLongitude) that combines the database with Open-Meteo (section 6.8).

  1. GET ?action=list → all favourites.
  2. POST ?action=add with name: the server looks up the coordinates with the geocoding API and stores name, country and coordinates. Unknown city → 404.
  3. POST ?action=delete with id (404 if nothing was deleted: rowCount()).
  4. GET ?action=weather → all favourites, each extended with temperature, text and icon of the current weather. If the request for one city fails, that city gets temperature: null – the other cities are still returned.
  5. Why should the client send only the name and not the coordinates? Write your answer in a comment.
