Chapter 3 – Loading external JSON data with PHP

Script: Chapter 3
Folder: /WEBAP/Exercises/ch03/ – one folder ex_xx per exercise. Comments marked TODO show where to write your code. Folders containing only a README.txt start from a copy of the previous exercise.

In all exercises, the PHP script loads the data from the external service and the browser only talks to your own server. The URLs of the services are defined in Exercises/common/config.php: include it with require_once __DIR__ . "/../../common/config.php"; and use the constants API_FORECAST, API_GEOCODING, API_RATES, API_CURRENCIES. Without internet, set OFFLINE to true in this file.

Exercise 3.1 – A first request

Folder: ch03/ex_01/   open folder   Files provided: weather.php

Write weather.php, which loads the current weather of Luxembourg (latitude 49.61, longitude 6.13) with file_get_contents() and json_decode(), and outputs an HTML page: Temperature: 6.4 °C, wind: 14.2 km/h (no AJAX yet).

  1. Display the whole decoded array with print_r() between <pre> tags first.
  2. Take the units from current_units.
  3. Display the time of the measurement.

Exercise 3.2 – PHP as proxy

Folder: ch03/ex_02/   open folder   Files provided: index.html, weather.php

Now the browser loads the weather with AJAX – but from your server, which loads it from Open-Meteo.

  1. weather.php builds the URL with http_build_query(), loads the answer and sends back a reduced JSON object in your own format, e.g. {"temperature": 6.4, "tempUnit": "°C", "wind": 14.2, "windUnit": "km/h", "time": "10:00"}.
  2. Test weather.php in the browser first. Compare the size of the original answer and of yours.
  3. index.html loads weather.php with $.getJSON() and fills the card.
  4. Why is it better to call the API from PHP than directly from the browser? Give three reasons in a comment in weather.php (section 3.1).

Exercise 3.3 – Currency converter

Folder: ch03/ex_03/   open folder   Files provided: convert.php, currencies.php, index.html

Use the Frankfurter API (constants API_CURRENCIES and API_RATES).

  1. currencies.php returns the list of currencies. When the page is loaded, both drop-down lists are filled with it (value = code, text = USD – United States Dollar). Select EUR and USD by default.
  2. convert.php receives amount, from and to, loads the rate (?base=…&symbols=…) and returns e.g. {"amount":100,"from":"EUR","to":"USD","rate":1.0864,"result":108.64,"date":"2026-11-20"}.
  3. Display 100.00 EUR = 108.64 USD and the date of the rate.
  4. If from and to are the same currency, convert.php answers directly with rate 1, without calling the API.

Exercise 3.4 – Error handling

Folder: ch03/ex_04/   open folder   Files provided: fetch.php, index.html, test.php

Real services fail: no network, wrong parameters, maintenance, changed URLs. Your scripts must react properly instead of showing PHP warnings.

  1. Write the function fetchJson($url) in fetch.php (section 3.6): it uses a stream context with a timeout of 5 s, checks the result of file_get_contents(), the HTTP status ($http_response_header[0]) and the result of json_decode(), and throws an Exception with a clear message in every error case.
  2. test.php receives a parameter case and calls fetchJson() with a correct or a faulty URL (see the TODO). On success it returns {"success":true,"temperature":…}; in case of an error, it catches the exception (try … catch), sets the HTTP status 502 (http_response_code()) and returns {"success":false,"error":"…"}.
  3. The client calls test.php with $.ajax(), displays the data in green or the error message in red (.done() / .fail() and xhr.responseJSON).

Exercise 3.5 – Chaining two requests: city → coordinates → weather

Folder: ch03/ex_05/   open folder   Files provided: cityWeather.php, index.html

The user enters a city name. cityWeather.php needs two requests:

  1. Geocoding (API_GEOCODING, name, count=1, language=en) returns the coordinates of the city. If the answer has no results, return status 404 and {"error":"City not found"}.
  2. With latitude and longitude, load the current temperature and weather code.
  3. Return e.g. {"name":"Ettelbruck","country":"Luxembourg","region":"Diekirch","latitude":49.85,"longitude":6.1,"temperature":5.1,"unit":"°C","code":3}. Not every result has admin1: use ??.
  4. The client displays the card or the error message. Enter in the field also starts the search.

You may use the function getJson() of config.php, which works like your fetchJson().

Exercise 3.6 – Caching answers

Folder: ch03/ex_06/   open folder   Files provided: index.html, rates.php

Exchange rates change only once a day – it makes no sense to ask the service at every click. rates.php stores the answer in the file cache/rates.json and uses it for one hour (section 3.9).

  1. If the cache file exists and is younger than 3600 seconds (filemtime(), time()), read it. Otherwise load the rates (base=EUR), save the answer in the cache file and use it.
  2. Add the key fromCache (true/false) and cacheAge (seconds) to the answer.
  3. The client displays the rates in a table and the information from cache (age 125 s) or fresh from the service. Click several times and watch the Network tab: how long does each request take?
  4. Create the folder cache automatically if it does not exist (is_dir(), mkdir()).
