Chapter 7 – Building the SPA client with jQuery

Script: Chapter 7
Folder: /WEBAP/Exercises/ch07/ – one folder ex_xx per exercise. Comments marked TODO show where to write your code. Folders containing only a README.txt start from a copy of the previous exercise.

Each exercise contains a working server API in the folder api/ (like the ones you wrote in chapter 6). Your task is the client: index.html, css/app.css and above all js/app.js, structured as in section 7.1 (configuration, state, API functions, render functions, events, start). The page must never reload.

Exercise 7.1 – Todo SPA

Folder: ch07/ex_01/   open folder   Files provided: index.html, api/, css/, js/

Write the client for the todo API (api/todos.php, documented in exercise 6.5).

  1. Write the function api(action, data, method) (section 7.2): it calls the API with $.ajax(), shows #loading during the request and displays the error message of the server in #message. It returns the promise, so that the caller can add .done().
  2. When the page is loaded, load all todos into the state and render them (template literals, section 7.3).
  3. Add a todo with the form, mark it as done with its checkbox, delete it with ✕ (event delegation, data-id). After each answer, update the state with the data returned by the server and call render() – do not reload the whole list.
  4. Filter buttons (all / open / done) and a counter.
  5. Double-click on a title replaces it with an input field; Enter saves (action update), Escape cancels.
  6. Show a short confirmation message (“Todo added”) that disappears after 3 seconds.

Exercise 7.2 – Notes SPA with views

Folder: ch07/ex_02/   open folder   Files provided: index.html, api/, css/, data/, js/

A notes application with two views and hash navigation (chapter 5) on top of the notes API (api/notes.php: list, add, update, delete).

  1. Routes: #list (all notes as cards, newest first), #new (empty form), #note/<id> (form filled with the note). Clicking a card opens it.
  2. The same form is used to create and to edit: a hidden field contains the id; without id the client calls add, with id update. After saving, update the state and go back to the list.
  3. The delete button (only visible when editing) asks for confirmation.
  4. The search field filters the cards in title and text while typing – on the client.
  5. Long texts are shortened to 120 characters in the list. Escape all texts (function esc(), section 7.3).

Exercise 7.3 – Weather dashboard

Folder: ch07/ex_03/   open folder   Files provided: analysis.md, index.html, api/, css/, js/

A SPA that combines internal data (favourite cities in the database) and external data (Open-Meteo). The API is ready: api/favorites.php (list, add, delete, weather – exercise 6.4) and api/forecast.php?lat=…&lon=… (7 days).

  1. #dashboard: one card per city with icon, temperature and text (action weather). The cards can be sorted by name or temperature (on the client). The ⟳ button reloads the weather.
  2. #add: a form with the city name. After adding, return to the dashboard. Unknown cities → error message of the server.
  3. #city/<id>: the 7-day forecast of the city as table, and a button to remove the city.
  4. Analyse: which tasks does the server do, which the client? Would you change something? Write 5 lines in analysis.md.

Exercise 7.4 – Bookshelf – a complete SPA

Folder: ch07/ex_04/   open folder   Files provided: index.html, api/, css/, js/

A reading list: search books in Open Library (external) and manage your own shelf (internal, table tblBook). This exercise is also an example of what your project (chapter 8) could look like.

  1. Server: api/books.php already offers search, list, add and delete. Add the action update (POST: id, status = want / reading / read, rating = 0 – 5): check the values, update the row and return the book. Test it with the API tester.
  2. #search: search form; results as cards with cover, title, author, year and a button + Add to shelf – or “on your shelf” if the book is already there. Adding a book twice → message of the server (status 409).
  3. #shelf: the books of the shelf with a drop-down list for the status and 5 stars for the rating (clicking a star saves the rating immediately). Filter buttons by status. A button removes the book.
  4. All changes are saved on the server and the state is updated with its answer – the page never reloads.
