Chapter 5 – Single page web applications

Script: Chapter 5
Folder: /WEBAP/Exercises/ch05/ – one folder ex_xx per exercise. Comments marked TODO show where to write your code. Folders containing only a README.txt start from a copy of the previous exercise.

A single page application (SPA) never reloads the page: views are shown and hidden with jQuery, and data is loaded with AJAX. These exercises practise the structure of a SPA: views, navigation with the URL hash, state and render functions.

Exercise 5.1 – Views and hash navigation

Folder: ch05/ex_01/   open folder   Files provided: index.html

The page contains three views (section.view). Only the view with the class active is visible.

  1. Write a function showView(name) that shows the view #view-name and hides all others, and marks the corresponding link in the navigation (class active).
  2. The links point to #home, #news, #contact. React to the event hashchange of window and show the view given by location.hash.
  3. When the page is opened, show the view of the current hash (e.g. index.html#news), or home if the hash is empty or unknown.
  4. Test the back and forward buttons of the browser and check that “Loaded at” never changes.
  5. Change the title of the browser tab according to the view (document.title).

Exercise 5.2 – Master–detail with internal and external data

Folder: ch05/ex_02/   open folder   Files provided: cities.json, index.html, weather.php

A classic SPA pattern: a list (master) and a detail view. The cities come from an internal source (cities.json), the current weather from an external one (the provided proxy weather.php).

  1. When the page is loaded, load cities.json once and store it in a global variable (the state).
  2. The list view shows the cities as links #city/3 (3 = id).
  3. The route #city/3 shows the detail view of the city (find it with Array.find()), and then loads its weather from weather.php?lat=…&lon=…. Show “loading …” meanwhile.
  4. An unknown id leads back to the list. Bookmarking index.html#city/4 must open the detail of Metz.
  5. Format the population with toLocaleString().

Exercise 5.3 – State and render function

Folder: ch05/ex_03/   open folder   Files provided: index.html

A shopping list that works entirely in the browser. Follow the pattern of section 5.4: all data is in one state object, the events only change the state, and one function render() redraws the view from the state.

  1. State: { items: [ {id, name, qty, done} ], filter: "all" }.
  2. The form adds an item (id: Date.now()). Clicking on an item toggles done; the ✕ button deletes it (event delegation, data-id, closest("li")).
  3. The filter buttons show all / open / bought items. A summary shows 3 of 5 items still to buy.
  4. Save the items in localStorage at every render and restore them when the page is loaded (JSON.stringify() / JSON.parse()).
  5. Why is it easier to keep the view correct with a single render() function than with many small changes of the DOM? Write your answer as a comment.
