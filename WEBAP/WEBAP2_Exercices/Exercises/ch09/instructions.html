Chapter 9 – Extracting data from existing HTML (web scraping)

Script: Chapter 9
Folder: /WEBAP/Exercises/ch09/ – one folder ex_xx per exercise. Comments marked TODO show where to write your code. Folders containing only a README.txt start from a copy of the previous exercise.

Some websites offer their data only as HTML pages, without an API. In these exercises you extract data from the fictional websites in /mock/sites – never scrape a real website without checking its terms of use and robots.txt (section 9.1). In PHP, use the constant SITES of common/config.php (SITES . "/news/").

Exercise 9.1 – String functions: headlines of a news site

Folder: ch09/ex_01/   open folder   Files provided: headlines.php, index.html

Open Lux Tech News and look at its source code (Ctrl+U).

  1. headlines.php loads the page with file_get_contents().
  2. Write a function between($text, $start, $end, $offset) that returns the text between two markers (strpos(), substr(), strlen(), section 9.3).
  3. Extract the page title and – in a loop – all headlines (<h2 class="headline">) with their link. Remove the tags with strip_tags().
  4. Return {"page": "…", "count": 5, "articles": [{"title": "…", "link": "…"}]}; the client displays the list.
  5. What happens if the website changes class="headline" into class="title"? Answer in a comment.

Exercise 9.2 – Regular expressions: prices of an online shop

Folder: ch09/ex_02/   open folder   Files provided: index.html, products.php

Analyse the source code of ByteShop.

  1. products.php finds all product blocks with preg_match_all() (pattern for <div class="product" id="…">…</div>, modifier s, section 9.4).
  2. In each block, extract the name, the price, the old price (if there is one) and whether the product is in stock. Convert the prices 1499,00 € into numbers (1499.0).
  3. Return the products sorted by price.
  4. The client displays a table; products on sale (old price) are highlighted and show the discount in %, sold-out products are grey. Below the table: number of products, cheapest product, average price.

Exercise 9.3 – DOMDocument and XPath: a bus timetable

Folder: ch09/ex_03/   open folder   Files provided: index.html, timetable.php

The timetable of bus line 16 is an HTML table. Extracting it with string functions would be painful – use the DOM instead (section 9.5).

  1. timetable.php loads the page into a DOMDocument (libxml_use_internal_errors(true)) and uses DOMXPath queries to extract: the names of the stops (table headers), the validity dates and, for every trip, the departure times and whether it is a low-floor bus.
  2. Return {"stops":[…],"validFrom":"…","validTo":"…","trips":[{"times":["05:40",…],"lowFloor":false}]}.
  3. The client loads the data once, fills the drop-down list with the stops and sets the time field to the current time. It displays the next 5 departures at the selected stop after the selected time (♿ for low-floor buses) and updates the list when the stop or the time changes – without a new request.

Tip: times in the format HH:MM can be compared as strings: "07:05" > "06:50".

Exercise 9.4 – SimpleXML: RSS feed and XPath

Folder: ch09/ex_04/   open folder   Files provided: feed.php, index.html

SimpleXML reads XML documents as objects (section 9.6).

  1. a) Lux Tech News also offers an RSS feed (XML). Read it with simplexml_load_string() and extract title, link, date (formatted 20/11/2026) and category of every item. Remember to convert values with (string).
  2. b) SimpleXML cannot read HTML directly. Load the ByteShop page into a DOMDocument, convert it with simplexml_import_dom() and find the names of all sold-out products with one xpath() query.
  3. feed.php returns both results; the client displays the news (with a category filter on the client) and the sold-out products.
  4. Compare: why is the RSS feed a better data source than the HTML page?

Exercise 9.5 – Parsing HTML with jQuery in the browser

Folder: ch09/ex_05/   open folder   Files provided: index.html

The ByteShop page is on our own server (same origin), so the browser may load it with AJAX and jQuery can search it like the current page (section 9.7).

  1. Load /mock/sites/shop/index.html with $.get() (the answer is a string).
  2. Convert it with $($.parseHTML(html)) and find the products with .find(".product"). For each product read the name, the category (attribute data-category), the price and the stock information with jQuery methods (find(), text(), attr()).
  3. Store the products as an array of objects and display them as table; fill the category list and filter the table on the client.
  4. Why would this not work with a page of another website? How could a PHP script help? (comment)

Exercise 9.6 – A JSON API for a website without API

Folder: ch09/ex_06/   open folder   Files provided: conclusion.md, index.html, api/

Turn the event calendar What's on into a JSON API (section 9.8).

  1. api/events.php extracts all events with DOMDocument/XPath and returns them in a clean format: {"title","date":"2026-11-27","time":"19:30","venue","category","price":28.0} (dates in ISO format, prices as numbers, 0 = free).
  2. Parameter month (e.g. 2026-12) filters on the server.
  3. The extracted events are cached for 10 minutes in api/cache/ (exercise 3.6).
  4. The website was redesigned: v2.html contains the same data with other markup. Write a second parser and detect the design automatically (parameter source=v2 loads the new page). If no parser finds events, answer with a clear error.
  5. The client is a small SPA: cards per event, month selection (new request) and “free events only” (client filter).
  6. Write in conclusion.md 5 risks of scraping compared to an official API.
